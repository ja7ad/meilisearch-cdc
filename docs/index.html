How it works

Many sources in. Many Meilisearch instances out.

A task joins a connector and a table to a destination and an index. The source position is captured before the snapshot, so streaming picks up exactly where the copy ended, with no gap. Checkpoints advance only after Meilisearch confirms the write.

  1. 1

    Snapshot

    Keyset-paginated copy of the table, chunked and back-pressured, with the replication position pinned first.

  2. 2

    Stream

    Inserts, updates and deletes are coalesced per batch and sent as pipelined, gzipped NDJSON tasks.

  3. 3

    Confirm & checkpoint

    At-least-once with idempotent writes. Even after kill -9, the task replays from its last checkpoint.

Features

Everything between your database and your search box

Built for production sync: safe by default, observable, and operable without touching a config file.

Snapshot then stream, no gap

The source position is captured before the copy and checkpointed only after Meilisearch confirms. Writes are idempotent, so replays are safe.

11 kinds of sources

PostgreSQL, MySQL/MariaDB, MongoDB, DynamoDB, CouchDB, SQL Server, CockroachDB, Kafka (Debezium), Redis Streams, webhook push and SQL polling.

Zero-downtime resync

Rebuild an index into a shadow index and swap it in. Search never drops while the data is reloaded.

Dead letter queue & guards

Rejected documents are isolated by bisection into a DLQ to replay or discard. Mass-delete and truncate guards hold the task; a primary key lock protects indexes.

Full index settings

Granular filterable attributes, embedders, synonyms, typo tolerance, ranking rules, faceting and more, with drift detection and one-click apply.

Schema check & diff repair

Compare source columns with index fields and coverage. Diff source and index document by document, field by field, and repair missing, stale and extra documents.

Many Meilisearch instances

Destinations with health checks, per-instance indexes, search playground, document browser, swap, compact, task monitor, dumps, snapshots and experimental features.

Reusable connectors

Saved source connections with encrypted credentials. Test them and browse tables, collections or topics before creating a task.

Alerts that reach you

Email, Telegram and webhook delivery for failed, held or retrying tasks, lag, DLQ growth, error bursts, stalled snapshots and Meilisearch outages.

  • Hand-written, allocation-light NDJSON encoder: 3.8× faster than reflection with 23× less memory.
  • Changes to the same document are coalesced within a batch; batches are pipelined.
  • Gzip, pooled connections, adaptive buffers, back pressure on the source.
  • Exponential backoff with jitter; oversized payloads are split automatically.

Security & operations

Ready for a team, safe for production

Accounts and roles

Email and password (argon2id), server-side sessions, CSRF protection and brute-force rate limiting. Viewer, moderator and admin roles; nobody changes their own role.

Primary administrator protection

The first admin owns the installation. Its role and account cannot be changed or deleted from the dashboard or the API, only by the operator CLI.

Invitations, password reset, audit log

Invitations are emailed when SMTP is configured. Logins, user changes and settings changes are recorded in the audit log.

Secrets encrypted at rest

AES-256-GCM with a key ring and rotation. Each ciphertext is bound to its record and field; secrets are never returned by the API. Every secret has a *_FILE variant for Docker and Kubernetes.

Observability

Prometheus metrics at /metrics, a live dashboard over SSE, structured logs and optional /debug/pprof for admins.

GitOps friendly

Import and export tasks, or declare them in a YAML file applied at startup with ${VAR} expansion.

Operator CLI on the server

Reset passwords, transfer ownership, sign everyone out, turn MCP off, revoke tokens and purge stored data by scope. It talks to the running service over its admin socket, or works on the data directory while the service is stopped.

meilisearch-cdc admin users reset-password --email you@example.com --generate
meilisearch-cdc admin purge sessions alert-events --yes

AI agents · Model Context Protocol

Let your AI agent operate the sync, within limits you set

A built-in MCP server (Streamable HTTP at /mcp) lets agents inspect tasks, check health and act on your pipelines.

  • Admins turn it on or off.
  • Random bearer tokens carry a role and can be rotated and revoked.
  • Tools and resources are allow-listed per role and checked on every call.
  • Mutating calls are written to the audit log.

      "type": "http",
      "url": "http://localhost:8080/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }

Get started

Running in a minute

Open http://localhost:8080. The first visit creates the admin account, then an onboarding flow guides you through connecting Meilisearch, connecting a source and creating your first sync.

Download the archive for your platform (see Download), extract it and run the binary. It needs no runtime and no configuration.

tar -xzf meilisearch-cdc_<version>_<os>_<arch>.tar.gz
cd meilisearch-cdc_<version>_<os>_<arch>
./meilisearch-cdc

Multi-arch image (linux/amd64, linux/arm64) on GitHub Container Registry. State lives in the /data volume.

docker run -d --name cdc -p 8080:8080 -v cdc-data:/data \
  ghcr.io/ja7ad/meilisearch-cdc:latest

Operator CLI inside the container: docker exec -it cdc meilisearch-cdc admin users list

Meilisearch and meilisearch-cdc together. With MEILI_URL set the service is pinned to that instance; leave it out to manage several destinations in the dashboard.

services:
  meilisearch:
    image: getmeili/meilisearch:latest
    environment:
      MEILI_MASTER_KEY: masterKey
    volumes: [meili:/meili_data]
  cdc:
    image: ghcr.io/ja7ad/meilisearch-cdc:latest
    depends_on: [meilisearch]
    environment:
      MEILI_URL: http://meilisearch:7700
      MEILI_API_KEY: masterKey
    ports: ["8080:8080"]
    volumes: [cdc:/data]
volumes: {meili: {}, cdc: {}}

Want a full demo with Postgres, 10,000 products and a running sync? Clone the repository and run docker compose -f deploy/docker-compose.yml up --build.

Configuration, sources, index settings, alerts, MCP and the operator CLI are covered step by step in the documentation.

FAQ

Questions, answered

What does each source need?

PostgreSQL uses logical replication (pgoutput) and needs wal_level=logical. MySQL 8 and MariaDB read the binlog with binlog_format=ROW and binlog_row_image=FULL. MongoDB uses change streams on a replica set; DynamoDB uses DynamoDB Streams; CouchDB and Cloudant the _changes feed; SQL Server its native CDC change tables; CockroachDB changefeeds; Redis Streams XREAD. Kafka carries Debezium JSON envelopes, which also covers Oracle, Db2, Cassandra and others. Anything with a database/sql driver can be polled with an incremental cursor column, and the webhook source accepts HTTP pushes.

What delivery guarantees do I get?

At-least-once with idempotent writes. The source position is captured before the snapshot, and checkpoints advance only after Meilisearch confirms a write. After a crash, even kill -9, the task replays from its last checkpoint. Failed tasks are re-applied without overwriting newer data, and if a source position is lost the task resyncs automatically.

Can one table feed several Meilisearch instances?

Yes. Destinations are named Meilisearch instances with their own URL, key, gzip, timeout and health check interval. Each task maps one connector and table to one destination and index, so several tasks can send one table to several instances.

What happens to documents Meilisearch rejects?

They are isolated by bisection into a dead letter queue, so the rest of the batch goes through. From the dashboard you can replay or discard them.

How do I rebuild an index without downtime?

Use zero-downtime resync: the task rebuilds into a shadow index and swaps it in when it is complete. Search keeps serving the old index until the swap.

Do I need a config file?

No. Everything is optional and managed in the dashboard. Environment variables and flags exist for the listen address, the data directory, pinning to one Meilisearch instance (MEILI_URL), the secret key, a bootstrap admin, and a YAML tasks file for GitOps. See the documentation.

How are credentials stored?

Encrypted at rest with AES-256-GCM, bound to their record and field, decrypted only when a connection opens and never returned by the API. The key is generated automatically if you do not provide one, and can be rotated with CDC_SECRET_KEY_PREVIOUS.

I locked myself out. What now?

On the server, run meilisearch-cdc admin users reset-password --email you@example.com --generate. The operator CLI also transfers the primary administrator, signs everyone out and turns MCP off. See docs/cli.md.

What is it built with, and what is the license?

Go 1.27 with the official meilisearch-go SDK, an embedded state store, and a dashboard in plain ES modules with Preact, embedded in the binary. For the license, see the repository.
